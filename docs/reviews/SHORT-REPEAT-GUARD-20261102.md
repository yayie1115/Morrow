# 短符号循环中止修复 2026-11-02

## 本轮证据

新追踪确认异常轮次实际发往 ofox Gemini 原生流式接口，收到 HTTP 200 和上游请求标识。界面显示时间与请求开始时间不同。本次不公开具体会话、请求 ID 或正文。

现有固定长度循环检测对短符号夹标点的循环触发过晚；原生传输将重复保护触发归为通用解析失败，导致回执无法表达准确的停止原因。

## 修改

- 在既有检测基础上补充短标点/符号循环检测，兼顾短表情和普通文本，不针对用户某条历史内容做删除或替换。
- 原生回复先检查尚未进入显示处理的上游正文，检测到持续循环后立即停止，不执行同一响应后续工具调用。
- 重复停止返回明确 REPETITION_ABORT 回执；追踪记录 repetition_abort，并区分 upstream_text 与 projected_text，便于以后识别生成与处理问题。
- 历史、人格、记忆、采样参数和思考过滤规则未修改。未额外调用收费模型。

## 验证和边界

编译通过。478 项离线测试：472 通过、6 跳过、0 失败。新增测试覆盖短循环停止、正常短表情和中文保留、原始循环文本不继续显示及工具不执行。

通过保护只能更早止损，不证明已经消除模型产生异常符号的根因；不能替代上游按请求 ID 排查。既有错误版本不会自动删除，用户已有编辑保持不变。

上线采用基线哈希校验、空闲检查、程序备份及平滑重载，无数据库结构变更。回退只恢复程序，保留全部消息和请求记录。
