# 失败助手草稿上下文隔离 2026-11-02

## 实际缺陷

不同通道共用 get_history。该路径此前不检查助手当前版本的 error / partial 状态，因重复中止的半截回复会再次作为正常助手发言送入下一轮。更换通道不能消除这个共用的回灌路径。此证据不等同于证明最初异常生成的唯一根因。

## 修复

仅在模型输入投影中隔离当前失败/未完成版本及明确符合既有失控检测的助手草稿，替换为准确的未完成状态提示。数据库正文、历史版本和前端可见内容不变；用户消息不受影响，用户修正后的有效版本继续正常使用。

成功工具结果和已实际生成的语音摘要仍保留，不因失败草稿隔离而让模型误以为工具未执行。不针对某个表情做全局删除或重写，不修改人格、采样设置或记忆规则。

## 验证与部署

- 独立数据库新增 5 项测试，覆盖失败版本、当前有效修正、旧错误版本、用户原文、成功工具及原数据库不变。
- 全量 483 项：477 通过、6 跳过、0 失败，编译通过。
- 在正式数据库上进行了只读输入投影对比，确认失败草稿不再进入普通回复历史，用户输入及工具调用顺序保持不变。未输出正文、未重发私人上下文、未额外调用收费模型。
- 上线前源码基线校验、聊天空闲检查和程序备份；平滑加载，服务 active，HTTPS 200。无数据库迁移和数据删除。

本次修好失败草稿再次进入上下文的明确缺陷；仍需后续正常聊天验证整体体验，不能把隔离测试宣称为根因完全消除。
